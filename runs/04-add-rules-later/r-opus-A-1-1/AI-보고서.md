## 2. 규칙을 어떻게 해석했는지
**규칙 1 (작성자 정산 90%)**
- 구매자는 지금처럼 가격 전액을 냅니다. 작성자에게는 90%만 들어갑니다.
- 남은 10%는 **어느 지갑에도 넣지 않습니다**. system 계정 같은 곳에 쌓으라는 말이 없었기 때문입니다. 수수료 금액을 따로 기록하지도 않고, 테이블 구조도 바꾸지 않았습니다. 구매 기록에 남는 것은 지금처럼 가격뿐입니다.
- 100원 단위 가격이면 90%가 정확히 나누어 떨어집니다.
- 규칙 이전에 저장된 100원 단위가 아닌 가격(예: 155)은 원 미만을 버립니다(139). 버린 금액은 수수료 쪽으로 봅니다. 이런 글도 구매는 계속 가능하게 했습니다.

**규칙 2 (가격 0 이상, 100원 단위)**
- 글 작성과 수정에서 가격을 새로 정할 때 검사합니다.
- 150 같은 값은 `400-8`로 거부합니다. 음수와 소수는 지금처럼 요청 검증 단계에서 `400-1`로 거부됩니다.
- 기존 상한 1,000,000도 그대로 둡니다.
- 수정할 때 가격을 빼고 보내면 기존 가격을 유지하므로, 규칙 이전의 글도 제목과 본문은 고칠 수 있습니다.

**규칙 3 (1회 충전 100,000 이하)**
- 100,000까지는 충전되고, 100,001부터 거부합니다(API에서는 `400-1`, 서비스를 직접 호출하면 `400-6`).
- 검사가 잔액을 건드리기 전에 이루어지므로 거부되면 잔액은 그대로입니다.
- 여러 번 나눠 충전하는 것은 막지 않았습니다(누적 잔액 상한 1,000,000,000은 기존 그대로).

## 3. 확인한 방법과 결과
- **테스트**: 변경 전 `./gradlew test`(JDK 21.0.2, H2) 결과는 50개 통과였습니다. 변경 후에는 58개 통과, 실패 0입니다.
- **새 테스트가 다루는 것**
  - 2500원 글 구매 시 구매자 −2500, 작성자 +2250.
  - 정산액 계산 경계값: 100→90, 155→139, 1→0.
  - DB를 직접 바꿔 만든 규칙 이전 가격(155, 1)의 글도 구매되고 정산이 맞는지.
  - 가격 0·100·2500·1,000,000은 작성 가능, 150·1·99·2550·999999는 400-8, −100·−1·100.5는 400.
  - 수정 때 150을 보내면 거부되고 제목·가격이 그대로인지.
  - 100,000 충전 성공, 100,001·500,000·1,000,000 거부 후 잔액 그대로, 서비스 직접 호출도 400-6.
- **실제 앱 확인**
  - jar를 `--server.port=18080 --spring.profiles.active=test`(메모리 DB라 dev DB 파일은 건드리지 않음)로 localhost에 띄웠습니다.
  - Python 스크립트로 HTTP 호출 13건을 확인했고 모두 PASS였습니다: 충전 상한, 가격 검증, 2500원 구매 후 작성자 +2250, 구매자 본문 열람.
  - 앱은 끝나고 종료했고 18080 포트가 비워진 것도 확인했습니다.
- **앱을 끄면서 생긴 일**: `taskkill`은 오류 없이 끝났는데 프로세스가 죽지 않았습니다. 차단 메시지는 없었습니다. 그래서 PowerShell `Stop-Process`로 종료했습니다. 직접 띄운 프로세스(PID 61044)였고 명령줄로 확인한 뒤 종료했습니다.
- **확인하지 못한 것**
  - dev 프로필(`./db_dev` 파일 DB)에 실제로 있는 데이터. 규칙 이전에 만들어진 100원 단위가 아닌 가격의 글이 실제로 있는지는 보지 않았습니다.
  - Swagger 문서에 어떻게 보이는지.
  - 수수료가 끼어든 상태의 동시성. 기존 동시성 테스트 3개는 통과했지만 부하 테스트는 따로 하지 않았습니다.
  - 응답 문구가 콘솔에서는 한글이 깨져 보였습니다. Windows 콘솔 출력 인코딩 문제로 보입니다. 한글 비교는 통과해서 데이터 자체는 정상입니다.

## 4. 기존 동작에 영향이 있을 수 있는 곳
- **고친 기존 테스트 3곳** (규칙 때문에 기대값 자체가 바뀌는 경우입니다)
  - `PostPurchaseFlowTest.t2`: 작성자 잔액 300 → 270.
  - `PostPurchaseConcurrencyTest.t1`: 판매자 잔액 100 → 90.
  - `PostPurchaseConcurrencyTest.t3`: 글 가격 50은 이제 규칙 위반이라 100으로 바꿨고, 최종 잔액 100/100 → 90/90.
- **API 동작 변화**
  - 100원 단위가 아닌 가격으로 글 작성·수정이 이제 400입니다. 새 결과 코드 `400-8`이 생겼습니다.
  - 충전 100,001 ~ 1,000,000도 이제 400입니다.
  - 구매 후 작성자가 받는 금액이 줄었습니다. 구매 응답의 형식은 그대로입니다.
- **잔액 총합**: 수수료 10%가 어느 지갑에도 쌓이지 않으므로, 회원 잔액의 합이 구매 때마다 줄어듭니다. 수수료를 플랫폼 계정에 넣거나 따로 기록해야 하는지는 정해 주셔야 합니다.
- **서비스 직접 호출**: `PostService.write`/`Post.updatePrice`에 음수를 넣으면 예전에는 `IllegalArgumentException`이었고 이제 `ServiceException(400-8)`입니다. API 경로는 요청 검증이 먼저 막으므로 차이가 없습니다.
- **규칙 이전 데이터**: 100원 단위가 아닌 가격의 기존 글은 구매는 되지만, 수정 때 같은 가격을 다시 보내면 거부됩니다.
