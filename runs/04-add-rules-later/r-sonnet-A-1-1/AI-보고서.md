  - `purchase()` 에서 작성자에게 90% 만 입금하도록 바꿨다.
- `src/main/kotlin/com/rest1/domain/post/post/controller/ApiV1PostController.kt`: 글 작성(`createItem`)에서 `validatePrice` 를 호출한다.
- `src/main/kotlin/com/rest1/domain/post/post/service/PostService.kt`: `write()` 에서도 `validatePrice` 를 호출한다.

  - 구매 테스트에서 작성자 잔액 기대값을 300 에서 270 으로 고쳤다.

  - 충전 상한 테스트 `chargeLimit`(100000 허용, 100001 거절 후 잔액 유지)을 추가했다.

**2. 규칙 해석**
- **수수료**
  - 구매자는 가격 전액을 차감하고, 작성자는 `가격 - 가격*10/100` 을 받는다. 가격은 100원 단위라 항상 딱 떨어진다.
  - 구매 기록(`Purchase`)의 금액은 전액 가격 그대로 둔다.
  - 수수료는 따로 적립하지 않고 사라진다. 플랫폼 계정이 없다고 보고 그렇게 했다.
- **가격**
  - 0 이상이고 100의 배수여야 하며, 위반하면 400(`400-3`)이다. 0(무료)은 허용한다. 기존 상한 10,000,000 과 정수 검사도 그대로다.
  - 글 수정 API 는 가격을 바꾸지 않으므로 검증이 필요 없다.
- **충전**: 1회 충전이 100,000 을 넘으면 400(`400-3`)으로 거부하고 잔액은 그대로다. 정확히 100,000 은 허용한다. 일반 입력값 검증과 같은 곳에서 걸러서 DB 에는 닿지 않는다.

**3. 확인한 방법과 결과**
- `./gradlew test --offline` 이 성공했고, 기존 테스트도 위에 적은 기대값 수정 외에는 그대로 통과했다.
- 새로 확인한 것은 가격 150 과 1 의 거절, 2500 의 허용, 충전 100000 의 허용과 100001 의 거절 후 잔액 유지, 구매 후 작성자 잔액 270(가격 300)이다.
- **확인하지 못한 것**
  - 실제 앱을 띄우는 `dev` 프로파일에서의 동작은 보지 않았다. 테스트가 쓰는 MockMvc 와 H2 만 썼다.
  - 동시 구매·충전 상황은 새로 시험하지 않았다. 기존 잔액 갱신 쿼리는 그대로 썼다.
  - 이미 저장된 데이터에 100원 단위가 아닌 가격이 있는 경우는 테스트하지 않았다.

**4. 기존 동작에 영향이 있을 수 있는 곳**
- 작성자 수령액이 가격의 90% 로 바뀌었다. 기존 테스트의 "작성자 300" 기대값이 의도적으로 270 으로 바뀐 이유다.
- 100원 단위가 아닌 가격으로 글을 쓰던 클라이언트는 이제 400 을 받는다.
- 100,000 초과 충전이 이제 400 이다. 예전에는 10,000,000 까지 허용됐다.
- 이미 저장된 비정상 가격(예: 150)은 그대로 구매할 수 있고, 작성자 수령액은 원 미만 버림이다. 극단적으로 가격 1원이면 작성자 입금은 0원이라 입금 호출을 건너뛴다.
- `PostService.write` 도 이제 가격 단위를 검증한다. 기존 호출부는 모두 기본값 0 이라 영향은 없다.
