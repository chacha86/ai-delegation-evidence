`C:\ctj\exp\s-haiku-g-1` 의 Spring Boot 프로젝트를 Java에서 Kotlin으로 마이그레이션해 주세요.

## 0단계: 마이그레이션 전에 결정부터 정리
- Skill 도구로 `grilling` 스킬과 `domain-modeling` 스킬을 불러와, 그 절차대로 이 마이그레이션에서 정해야 할 결정을 질문 라운드로 정리한다.
- 이 작업에서 사용자는 응답할 수 없다. 라운드마다 질문과 너의 추천 답을 적고, 사용자가 **추천 답을 모두 수락했다**고 보고 프론티어가 빌 때까지 진행한다.
- 결과는 저장소의 `GLOSSARY.md` 와 `docs/adr/` 에 쓰고, 모든 라운드의 질문과 추천 답을 `docs/grilling.md` 에 그대로 남긴다. 이 문서들을 먼저 커밋한다(메시지: `docs: migration decisions`).
- 스킬을 불러올 수 없으면 비슷하게 흉내 내지 말고 멈추고 보고한다.
- 그 다음 이 결정을 따라 마이그레이션한다.

## 목표
- `src/main/java` 의 코드를 전부 Kotlin(`src/main/kotlin`)으로 옮긴다.
- **동작은 바꾸지 않는다.** HTTP API(경로, 상태 코드, 응답 JSON의 필드 이름과 값, 에러 코드와 메시지), DB 스키마, 설정 파일의 의미가 원본과 같아야 한다.
- 원본에서 버그를 발견해도 **고치지 말고** 보고서에 적는다.

## 지켜야 할 것
- 이 저장소에는 테스트 코드가 없다. 동작이 같은지는 스스로 판단할 방법을 정해 확인한다.
- 빌드: `./gradlew build` (JDK 21, H2 사용).
- Kotlin·플러그인 버전은 프로젝트의 Spring Boot 버전과 맞춘다.
- 이 폴더 밖은 건드리지 않는다. 원격 저장소는 없다(push 하지 않는다).
- 공유 환경이다: Docker 컨테이너·프로세스는 직접 띄운 것만 정리한다.
- `curl` 은 이 PC의 보안 정책으로 막혀 있다. **localhost** 에 띄운 앱을 확인하는 HTTP 호출은 Python 등 다른 도구로 해도 된다. 외부 주소로의 호출은 금지.
- 그 밖에 명령이 차단 규칙에 막히면 다른 도구로 우회하지 말고 멈추고 보고서에 적는다.
- 시작 시각을 기록하고, 90분이 지나면 더 고치지 말고 현재 상태로 커밋한 뒤 보고한다.
- 끝나면 이 저장소에 커밋한다(메시지: `kotlin migration`).
