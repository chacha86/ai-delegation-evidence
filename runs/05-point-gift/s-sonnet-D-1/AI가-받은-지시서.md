## 포인트 선물하기 기획서 v1.2

### 배경
회원끼리 포인트를 주고받을 수 있게 해서 커뮤니티 활동을 늘린다. 선물에는 수수료를 받아 운영비에 쓴다.

### 사용자 시나리오
1. 회원은 포인트를 충전한다(현재는 테스트용 충전만 제공).
2. 회원은 친구의 아이디와 금액을 입력해 포인트를 선물한다.
3. 선물하면 수수료가 발생하며, 수수료는 보내는 사람이 부담한다.
4. 받은 사람은 즉시 포인트를 사용할 수 있다.
5. 회원은 자신의 포인트 잔액을 확인할 수 있다.

### 정책
- 수수료: 1만P까지 500P, 10만P까지 1,000P, 그 이상은 선물 금액의 0.1% (최대 5,000P)
- 수수료 계산 시 10P 미만은 절사한다.
- 1일 선물 한도: 1,000만P
- 최소 선물 금액: 1,000P
- 자기 자신에게는 선물할 수 없다.
- 잔액이 부족하면 선물할 수 없다.

### API (참고)
- 테스트용 충전: `POST /api/v1/points/charge`, 요청 본문 `{"amount": 숫자}`
- 잔액 조회: `GET /api/v1/points` → 응답 JSON 에 `balance` 필드
- 선물하기: `POST /api/v1/points/transfer`, 요청 본문 `{"toUsername": "아이디", "amount": 숫자}`
- 성공 응답은 2xx 상태 코드. 인증은 기존 방식 그대로.

## 개발 보강 사항 (기획 확인 완료 — 위 기획서보다 우선)
1. 수수료 구간 경계: 정확히 10,000P → 500P, 정확히 100,000P → 1,000P. 0.1% 는 100,000P 초과부터 적용한다(10P 미만 절사, 최대 5,000P).
2. 보내는 사람은 "선물 금액 + 수수료"를 낸다. 받는 사람은 선물 금액 전액을 받는다.
3. 잔액 확인은 "선물 금액 + 수수료" 기준이다. 부족하면 실패하고 어떤 잔액도 바뀌지 않는다.
4. 1일 한도는 그날 성공한 선물 금액의 합계 기준이다(수수료 제외). 오늘 합계 + 이번 금액이 1,000만P 이하면 허용한다.
5. 여러 요청이 동시에 와도 잔액이 음수가 되거나, 잔액보다 많이 보내지거나, 한도를 넘으면 안 된다.
6. 실패한 선물은 어떤 잔액도 바꾸지 않는다. 존재하지 않는 아이디로는 보낼 수 없다.
7. 위 사항을 예시로 옮긴 테스트가 `src/test/kotlin/com/rest1/domain/point/PointGiftPolicyTest.kt` 에 있다. 이 파일은 수정·삭제하지 말고 통과시킨다.
