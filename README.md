저장소를 받은 뒤 **`viewer.html` 을 브라우저로 여세요.** 설치할 것은 없습니다.
- **① 따라 보기** 탭 (처음이면 여기): 질문 7개를 차례로 넘기며 "AI가 한 말"과 "실제 결과"를 나란히 봅니다.
- **② 발견별 근거 모음** 탭: 문서의 주장마다 "원자료 보기" 버튼이 있고, 누르면 해당 파일의 그 부분으로 이동해 노란색으로 표시합니다.
- **실행 46개** 탭: 실행마다 AI가 받은 지시서 · AI 보고서 · 채점 결과 · AI가 바꾼 코드를 탭으로 봅니다.

## 폴더 안내

| 폴더 | 들어 있는 것 |
|---|---|
| `docs/` | 수강생용 정리 문서 |
| `prompts/` | AI에게 준 지시서 원문 (조건별) |
| `runs/<실험>/<실행>/` | 실행 하나의 결과: `AI가-받은-지시서.md`(그 실행이 실제로 받은 지시서 원문), `AI-보고서.md`(AI가 낸 보고서 원문), `AI가-바꾼-코드.patch`(AI가 고친 코드 전체), `채점-결과.txt`(숨긴 테스트 항목별 통과/실패와 실제 숫자), `실행환경-자동주입.md`(아래 참고) |
| `hidden-tests/` | AI에게 보여 주지 않은 채점 테스트와 회사 의도 |
| `reference/` | 채점 기준이 된 정답 구현 (강사 쪽 AI 작성) |
| `validation/` | 숨긴 테스트 자체를 검증한 기록 (버그를 심었을 때 잡는지, 반복해도 같은지) |
| `predictions/` | 실행 **전에** 적어 둔 예측 (틀린 예측 포함) |
| `notes/` | 실행 중 관찰 기록 |
| `results/` | 전체 채점 결과 (한 줄 = 실행 하나, JSON) |

### 실행 이름 읽는 법

| 이름 | 뜻 |
|---|---|
| `s-<모델>-t/n/g-<회차>` (01) | 마이그레이션. t = 기존 테스트 줌, n = 안 줌, g = 안 줌 + grilling 스킬 |
| `p-<모델>-A/B/C-1` (02) | 결제 v1. A = 기능만, B = 정책을 말로, C = 정책 + 예시 테스트 |
| `q-<모델>-A/B/C-<회차>` (03) | 결제 v2. 02 + 회사 규칙 3개(수수료 10%, 충전 한도 10만, 100원 단위) |
| `r-<원본>-<회차>` (04) | 03의 A 결과물에 "회사 규칙 추가해 줘"만 다시 요청 |
| `s-<모델>-P/D/O-<회차>` (05) | 포인트 선물. P = 기획서 복붙, D = 기획서 + 개발자 보강, O = "기획서대로 만들어줘" 한 줄 |

## 문서의 주장 → 확인할 파일

### 발견 1. 같은 지시를 줘도 결과는 매번 다르다
- 9개 구현 비교: `runs/02-payment-v1/p-*/AI가-바꾼-코드.patch` 를 나란히 열어 보세요. 잔액 위치(지갑 테이블 vs 회원 컬럼), 동시성 방식, 응답 코드가 서로 다릅니다.
- 같은 모델·같은 지시, 다른 실패: `runs/03-payment-v2/q-haiku-A-1/채점-결과.txt`(동시성 실패) vs `q-haiku-A-2/채점-결과.txt`(작성자 적립 실패)

### 발견 2. 말하지 않은 규칙은 AI가 "그럴듯하게" 채운다
- 지시서: `prompts/02-03-payment-A-기능만.md` (회사 규칙 없음) vs `prompts/03-payment-B-정책(v2, 회사규칙 포함).md`
- 충전 한도를 스스로 정한 흔적: `runs/03-payment-v2/q-sonnet-A-1/AI-보고서.md`(1,000만 원), `q-opus-A-1/AI-보고서.md`(100만 원), `q-haiku-A-2/AI-보고서.md`(10억)
- 채점: 각 `채점-결과.txt` 의 `R1 R2 R3` 줄 (예: "100,001 응답 200, 잔액 200001")

### 발견 3. "락 걸었습니다" ≠ 동시성 문제없음
- AI의 말: `runs/03-payment-v2/q-haiku-A-1/AI-보고서.md` ("비관적 잠금", "동시 요청은 확인하지 못했다")

- 원인 코드: 같은 폴더 `AI가-바꾼-코드.patch` 에서 `lockWallets` 검색 → `getOrCreate`(먼저 읽음) 다음 `findByMemberIdForUpdate`

- 강사 쪽 AI도 같은 실수: `validation/05-hidden-test-검증-1차(정답 구현 흔들림 발견).txt` 의 `ref-2 ... 12/13`

- Opus 자체 테스트는 서비스 직접 호출: `runs/05-point-gift/s-opus-P-2/AI가-바꾼-코드.patch` 에서 `PointServiceConcurrencyTest` 검색 (`pointService.transfer(...)`)

- 관리자 열람: `runs/02-payment-v1/p-opus-A-1/AI가-바꾼-코드.patch` 에서 `isAdmin` 검색 / 채점은 `채점-결과.txt` 11/11

## 결과를 보기 전에 적은 예측
`predictions/` 의 파일은 실행 **전에** 썼습니다. 예를 들어 "기능만 주면 대부분 실패할 것"(02), "모호한 문장은 실행마다 해석이 갈릴 것"(05)은 **틀렸고**, 그대로 남겨 두었습니다.

## 한계
- 조건마다 1~3회. "항상 그렇다"가 아니라 "해 본 곳에서는 그랬다"입니다.
- 학습용 작은 프로젝트, DB는 H2입니다.
- 채점 테스트도 AI가 만들었습니다. `validation/` 처럼 버그를 심어 검증했지만 모든 경우를 덮지는 못합니다.
- **실행 환경이 지시서 뒤에 붙인 글이 있습니다.** 이 PC에 설치된 플러그인(context-mode)이 AI가 시작될 때마다 도구 사용 안내문(출력을 줄이는 도구를 쓰라는 내용)을 자동으로 붙였습니다. 과제(결제·동시성 등)와 관련된 내용은 없고, 46개 실행 모두 **똑같은 글**을 받았습니다(내용 해시 동일). 각 실행의 `실행환경-자동주입.md` 에 원문을 그대로 두었습니다.
- 개인 경로와 계정 정보는 `<user>`, `<임시폴더>`, `<session>` 으로 바꿨습니다.
